Wide-page blocks
Reference sheet — maps, images, tables, charts. Copy what you need.
§1 · Page width

A visual page usually wants more than the 720px default. Change .page and .nav-inner together — changing only .page leaves the nav bar narrower than the content, which reads as a bug. 900px is what Global Reach uses and is a good default for a map or a wide table.

§2 · Figure — the wrapper for any visual

One container for maps, images, charts and embedded SVG, so every visual sits in the page the same way. Height is never fixed: the box grows with its content, which is what keeps a map or a wide chart from getting its own little scrollbar on a phone. Caption goes below the box, in tertiary text.

Caption. Say what the reader is looking at and where the numbers came from — this is also where a source note belongs.

For a raster image (a screenshot, a photo), put an <img> directly inside .figure. It gets width:100%; height:auto automatically, so it scales. Always write real alt text. Export at roughly twice the display width for retina screens, then compress — a portfolio page should not ship a 4MB PNG. Screenshots of dark-mode UI look broken on a light page and vice versa; if the image has a background, prefer one with a neutral or transparent backdrop.

§4 · Data table — Structify exports and other tabular data

The table below is generated from a JS array at the bottom of this file rather than hand-written as HTML. That's the same pattern pages.js uses, and the same one Global Reach uses for its city list: paste the export once, and the table re-renders. Editing 40 rows of <td> by hand is where mistakes come from.

Getting Structify output in: export to CSV, then convert it to a JS array of objects — any AI session will do that conversion in one pass. Keep the array in the page. If a dataset is big enough that pasting it feels wrong (say past a few hundred rows), that's the signal to save it as a separate .json file and fetch() it, the way Global Reach fetches its world atlas.

Numeric columns get class="num", which right-aligns them and turns on tabular figures so the digits line up in a column. Leave text columns alone — tabular figures make prose look loose.

§5 · Charts — color rules

Series colors are defined once as --series-1 through --series-5 at the top of the file, with separate steps for dark mode. Assign them in order, top down. Don't pick by taste and don't invent a sixth hue — the order is validated, and picking around it is how two series end up indistinguishable.

The cap depends on the chart type, because it depends on whether any two series can end up touching:

  • Bars, stacked bars, lines — series sit in a fixed order, so only neighbors need to separate. Up to 5 slots is fine.
  • Maps, scatter, bubble — any two categories can land next to each other, so every pair has to separate. Three colors is the honest cap. Past three, either fold the rest into "Other," split into small multiples, or add a second channel: different marker shapes, or direct labels.
This applies to the map on Global Reach. Its four region colors don't fully separate — teal against blue is close enough that some readers, and most colorblind readers, can't reliably tell them apart. The page gets away with it because color isn't doing the work alone: there's a legend, a hover tooltip naming every city, and a full city list underneath with a colored pip beside each entry. That's the "second channel" rule being satisfied by accident. If you rebuild that map, either use the first three slots plus a distinct marker shape for the fourth region, or keep four colors and keep the city list — but don't ship four colors with no list.

Two more rules worth keeping: grid lines and axes are always gray (--chart-grid, --chart-axis), never a series color; and labels and values stay in text colors — a colored pip beside a label carries the identity, the text itself doesn't need to be colored. And a legend is required as soon as there are two or more series.

§6 · Tooltip

Any chart or map should say what a mark is on hover. One #tooltip div lives at page level and gets moved on mousemove; global-reach.html has the working version to copy — about eight lines.
